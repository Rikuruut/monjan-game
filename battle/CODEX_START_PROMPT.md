# Codexへの初回指示（そのまま貼り付け可）

あなたはReact・TypeScriptのゲーム開発担当です。子ども・家族向けイベント用のブラウザゲーム「モンじゃん！」の試作版を作ってください。

## 読み込む資料
- `AGENTS.md`
- `docs/GAME_SPEC.md`
- `docs/SCREEN_SPEC.md`
- `docs/DATA_SPEC.md`
- `docs/TEST_CASES.md`
- `docs/reference/` にある手描き画面遷移図・バトルレイアウト・カード見本
- `public/data/` 以下のJSON、`public/monsters/` 以下のPNG

## 今回の開発範囲
- React + TypeScript + Vite。スタイルはCSSを基本とし、PC横長画面16:9（1920x1080基準）に適応。
- 画面はタイトル → ルール説明（バトル画面上のポップアップ） → バトル → 勝利/敗北/引き分け結果 →「遊んでくれてありがとう」→ タイトルに戻る。
- 初回はユーザーの仮モンスターとCPUの仮モンスターを、`public/data/game-config.json` とJSONからロード。画像も同じIDに紐づける。
- バトル画面は上段左右に2体のモンスター。左プレイヤー、右CPU。画像の上に⚔、下に残り♡。中央にVS。下段に大きいグー✊・チョキ✌️・パー✋の3ボタンと星レア度表示。
- 各ラウンド開始時、プレイヤーのグー・チョキ・パーに★1/★2/★3を重複なしでランダムに割り当てて見せる。CPU側でも独立に割り当てるが非公開。
- CPUの手はグー・チョキ・パーから一様ランダムに選ぶ。プレイヤーが手を選択したあと、双方の手・星・勝敗を表示。
- 通常のじゃんけんで優劣があれば星を無視。勝った方が自分の⚔の数だけ相手の♡を減らす。
- 同じ手なら星が多い方が勝ち、同様にATK分のダメージ。手も星も同じならどちらも勝たず、双方の♡を1個減らす。
- HPは♡1〜5個、ATKは⚔1〜3個。JSONではHP1000〜5000、ATK1000〜3000を1000刻みで持つ。内部処理はハート個数で管理してよい。
- 片方のみHP0なら勝ち/負け結果画面。両方同時HP0なら引き分け専用画面で「最後は本物のじゃんけん！」を表示し、スタッフと子どもが現実のじゃんけんをしたあと手動で終了画面へ進む。
- 属性はバトル結果に影響させない。カード印刷機能も今回は作らない。
- 画面遷移・ゲームルールは文書を優先し、現時点で未決定の内容はゲームの基本ルールを壊さない最小限の仮仕様で実装し、その仮定を明記する。

## 実装の進め方
1. プロジェクトを初期化し、画面遷移の骨組みを作る。
2. Monster型・JSON読み込み・サンプル画像表示を作る。
3. ゲームロジック（手の勝敗、★シャッフル、攻撃、引き分け）をUIから分離して実装する。
4. バトル画面、結果画面、終了画面を実装する。
5. ボタン連打防止・画面復帰時の状態初期化・異常JSONの扱いを入れる。
6. `docs/TEST_CASES.md` に沿ってVitestの単体テストを作る。
7. `npm install`, `npm run dev`, `npm run build`, `npm run test` に相当するスクリプトを整えて実行し、結果を報告する。

## 重要な制約
- 今回は画像生成API・ChatGPT Plusへの自動接続・スマホ撮影・プリンターへの送信は実装しない。
- じゃんけんの★レア度をモンスターJSONに固定で書かない。
- CPUがプレイヤーの手を見てから有利な手に変えることは禁止。選択は独立ランダム。
- 仕様と異なる新ルール（属性相性・特殊技・対人戦・勝手なラウンド制限）は追加しない。
- 日本語UI、子どもが分かりやすい短い文章、パステルカラーと水彩風イラストの雰囲気を重視する。

完成後は、動作確認手順と各画面のスクリーンショット、テスト結果を示してください。
