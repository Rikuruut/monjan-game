# モンじゃん！— React / TypeScript Webゲーム

子ども向け「生き物＋持ち物」AIモンスター生成・じゃんけん対戦イベントの**ゲーム部分**を試作するための素材一式です。

## 最初に読む順番
1. `CODEX_START_PROMPT.md` — Codexへの初回指示文（コピーして使う）
2. `docs/GAME_SPEC.md` — 最新の確定ゲーム仕様
3. `docs/SCREEN_SPEC.md` — 画面遷移とレイアウト
4. `docs/TEST_CASES.md` — 動作確認項目
5. `public/data/game-config.json` — 初期プレイヤー・CPUの設定

## プロジェクト構成
- ゲーム本体：`src/`
- モンスター画像：`public/monsters/`
- モンスターデータ：`public/data/monsters/`
- タイトル／バトル／結果ロゴ：`public/assets/monjan-title-logo.png`
- BGM：`public/audio/adorable.mp3`
- 開発仕様：`docs/`

## 注意
- このフォルダの `docs/GAME_SPEC.md` を仕様の優先ソースとする。以前のWord仕様書には古い数値が残っている場合があります。
- モンスターの名前・属性・数値・説明文は**開発用サンプル**であり、正式なAI生成結果ではありません。
- 画像生成API・スマホ写真アップロード・カード印刷は初回の開発対象外。
- `docs/reference/` はユーザーの手描きスケッチと参考用カード画像です。カード参考画像中の文字はコピーしないこと。

## ゲームルール（変更なし）
- ★（レア度）の制度は2026年11月4日にやめました。通常のじゃんけんで判定し、同じ手は連打勝負（多く押した方の勝ち、同じ回数なら双方のHPが1減る）。
- 勝者のATK（⚔の数）だけ相手のHPを減らし、HPは0未満になりません。
- CPUの手はプレイヤー選択後に公開します。
- CPUはプレイヤーの選択を参照せず、グー・チョキ・パーからランダムに選びます。
- 同時にHPが0になった場合は引き分け画面へ進み、会場で本物のじゃんけんを行います。
- 判定理由は `hand`（じゃんけん）と `mash`（連打勝負）。ピンチの必殺技は `special`。

## サウンド
- BGMは `Adorable.mp3` を使用し、タイトル表示時に再生を試み、バトル・勝敗・カード獲得・タイトル復帰後まで途切れず継続します。
- BGM音量とSE音量は別々のスライダーで調整でき、サウンド全体をON/OFFできます。
- ブラウザが初回の自動再生を止めた場合は、スタート操作を音声再生の合図として再試行します。
- スタート操作で `AudioContext.resume()` の完了を確認し、再開後にSEを鳴らします。複数の再開要求は共有Promiseでまとめ、二重再生を防ぎます。
- 初期音量はBGM 55%、SE 90%です。BGMよりSEを聞き取りやすくし、それぞれ個別スライダーと全体ミュートで調整できます。
- 現在のSEは、召喚・選択・レア度抽選・じゃんけん・公開・★対決・あいこ・属性別攻撃・命中・HP減少・勝敗・カード獲得などをWeb Audioで合成した仮音源です。
- Web Audio非対応、AudioContext作成失敗、resume失敗、再生準備失敗は、開発者ツールのConsoleへ `[モンじゃん！ SE]` 付きで表示します。
- SEの最終出力は従来の5倍へ引き上げています。各toneの補正と上限に加えて最終段へピークリミッターを通し、大音量時のクリップや極端な音割れを抑えます。
- BGMとSEはローカル素材／ブラウザ内合成のため、ゲーム進行にネット接続は不要です。

### 実ブラウザでのSE確認手順

自動テストでは音の波形や再生予約を検証できますが、会場端末のスピーカーから聞こえる音量はブラウザで確認してください。

1. `npm.cmd run dev` を実行し、表示されたURLをChromeまたはEdgeで開く。
2. ブラウザのタブとWindowsの音量ミキサーがミュートになっていないことを確認する。
3. 画面右上を「サウンド ON」、BGM 55%、SE 90%にして「スタート！」を押す。
4. 通常ゲームを進め、スタート、召喚、じゃん・けん・ぽん、CPU公開、★比較またはあいこ、攻撃、命中、HP減少、勝利／敗北、カード獲得の各タイミングでスピーカーから音が聞こえることを確認する。
5. BGMとSEのスライダーを別々に動かし、片方だけの音量が変わることを確認する。全体ミュートをOFFからONへ戻した後も、次のゲーム操作でSEが再開することを確認する。
6. 音が聞こえない場合は、開発者ツールのConsoleで `[モンじゃん！ SE]` またはBGM用の `[モンじゃん！]` の内容を確認する。Networkで `/audio/adorable.mp3` が404になっていないことも確認する。SEはWeb Audio合成のため、個別のSEファイル通信はありません。

## 暫定実装上の仮定
- HPは判定直後ではなく、命中演出に合わせて画面へ一度だけ反映します。ゲームの判定ルール自体は変更していません。
- ラウンド上限と時間制限は、仕様どおり設けていません。

## 撮影・合体の画面との結合(2026年11月2日)
このフォルダは `monjan-game` リポジトリの `battle/` に入り、撮影・合体の画面(`../generator/`)とつながりました。くわしくは `../CLAUDE.md`。

- 流れ:タイトル → スタート → 撮影・合体の画面 → 「たたかう!」→ `/battle/?photo=<id>`(タイトルを飛ばしてルール説明から)→ 結果 → ありがとう → タイトル
- `npm.cmd run build` の出力先は `../generator/static/battle/`(サーバーが `/battle/` で配る。`vite.config.ts` の `base`)。`npm.cmd run dev` はこれまでどおり単体で動く
- 画像・音・JSON のパスは `src/integration.ts` の `assetUrl()` で `/battle/` を付ける(JSON そのものは変えていない)
- 生成したモンスターは `/api/battle-monster/<id>` から読む。CPU は見本のモンスターからランダム
- 会場の3つのボタン(← / Enter・Space / →)で操作できる。バトルでは左からグー・チョキ・パー、ほかは中ボタンで進む
- 撮影・合体の画面の性質(あつい・みず・でんき・かたい・とがってる・やわらかい)を、属性の見た目と音(火・水・光・土・風・草)に対応させた
- `package.json` の版を `latest` から package-lock の版に固定した
- 開発者メニュー(D キーか右下の ⚙。`src/DevMenu.tsx`・`src/devTools.ts`):画面へとぶ・勝ち負けを決める・♡を1に・モンスターの JSON と、撮影・合体の画面と共通の ページ・通しの自動プレイ・作ったモンスターで戦う。`npm.cmd run dev` の単体では、作ったモンスターの一覧は出ない(サーバーがないため)

### 結合のときに決めた仮定
- 生成したモンスターの ⚔ は 1〜3、♡ は 3〜5 をランダム(♡1〜2 だと1回で終わるため。仕様の範囲内)
- 生成したモンスターと戦う CPU は、見本の3体からランダム

## 見た目の刷新(2026年11月2日。ブランチ experiment/battle-custom の実験)
撮影・合体の画面(`../generator/static/themes/fusion`「たんじょうのもり」)と同じ色・字体・部品にそろえ、戦闘を見やすくした。元の `src/styles.css` と `App.tsx` は `../generator/archive/20261102_before_battle_restyle/`。

- 1920×1080 の舞台を窓に合わせて拡大縮小する(`src/stage.tsx`。撮影・合体の画面の `fitStage` と同じ)。中はすべて px で配置
- CSS は `src/styles/` に分けた:`base`(色・舞台・カード・操作盤・お知らせの帯)/ `title` / `battle`(配置・手のぶつかり・実況の帯・ルール説明)/ `effects`(召喚・攻撃・命中・最後の一撃)/ `result`(結果・ありがとう)/ `devmenu`
- 背景は草原の絵のまま。モンスターは誕生カードと同じ作りのカードで出し、自分 = 若葉・相手 = 花びら の色で分ける
- 下の操作盤は会場の3つのボタンと同じ並び(`src/Deck.tsx`)。バトルでは手のカードが その場所に並ぶ
- 戦闘:ぽん!で2つの手が真ん中でぶつかり、勝った手が光る / 同じ手は あなた と CPU の連打ゲージ / ピンチで勝つと必殺技のカットインと特大の攻撃 / 下の帯に いま起きていることを大きく / タイプごとの飛び道具(`src/BattleEffects.tsx`)/ 命中のヒットストップ・画面のゆれ(ダメージで強さが変わる)/ 大きなダメージの数 / 最後の一撃で倒れたカードが沈む
- 時間:攻撃 480 → 700ms、命中 420 → 600ms、結果 2300 → 2000ms(1ラウンドで +0.5秒ほど)
- 字体は サーバーの `/static/vendor/fonts/gacha.css` を `src/main.tsx` で読む。`npm.cmd run dev` では `vite.config.ts` の proxy で 8000 番から借りる(なければ代わりの字体)
